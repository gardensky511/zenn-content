## 🌼 はじめに

こんにちは、みなさん AI 使ってますか？私ももう AI なしではやっていけない体になってしまいました。

ですが、AI 関連でなんとなく知ってるようで実はあまりわかってないもの多いなーと思ったので、そのなんとなく AI 知識を一つずつ紐解いていく記事を書きたいと思いました。

その1番目の記事として、そもそも AI と ML・DL・LLM はなにでどういう関係性なのかを話したいと思います。

:::message

## 1. AI (Artificial Intelligence)

### 初期の AI

AI は *Artificial Intelligence* の略で、人工的な知能という意味ですね。

「考える機械」というアイデア自体は、少なくとも古代ギリシャの頃からありました。そして1950年代にはすでにAIの研究も行われていました。

ですが、初期のAIは、高い思考力が必要でもルールが明確に決まっている作業は得意でしたが、逆に**ルールが明確でない作業は苦手**でした。

例えば、チェスや数学的な証明はできても、ルールは特にないけど人間が何も考えずにやっていること（友達の顔を見てそれが友達だと認識するなど）はできなかったです。

![](/images/ai-ml-dl-llm-basics/early-ai-can-cannot.png =700x)
*AI が昔から得意なことと、長く苦手だったこと*

普通の人にはとても難しい数学的な証明はコンピュータがわりと早くからできたのに、普通の人なら誰でもできる顔の見分けは長い間できなかったというのは、アイロニーですよね。

### AI に知識を教える
ルールがないことが苦手なら、AI にすべてのルールを教えてあげればいいかもしれません。このように、世の中の常識やルールを人がコンピュータに入力し、推論させる方法を、知識ベース（*knowledge base*）を使ったアプローチと言います。

実際にそれに挑戦した Cyc（1980年代〜）というプロジェクトがありました。Cyc は推論エンジンと、知識を集めたデータベースでできていて、その知識はスタッフがいちいち手で入力していました。

もう既に気づいてると思いますが、このやり方はかなり厳しかったです。世の中には常識やルールが多すぎて、それを人が全部言葉にするのはとてつもなく大変です。

例えば、Cyc はこういう推論を出しました。

![](/images/ai-ml-dl-llm-basics/cyc-fred-shaving.png =617x)
*Cyc が出した推論*

人間なら、電気シェーバーを持っているからといってそれが体の一部になるわけじゃないことは当たり前にわかります。でも機械には、その「当たり前」をすべて教えないと、変な結論にたどり着いたりします。

つまり AI に必要とされるのは、人が入力したルールではなく、**データから自分でパターンを見つけ出す能力**です。

## 2. 機械学習(Machine Learning)

先ほど、人がすべての知識を教えることはできないという話をしました。そこで必要になるのが機械学習（ML、*Machine Learning*）です。知識を人が全部書く代わりに、データから自分で見つけさせます。

ML の大事な考え方の一つが、**特徴量**（***feature***）です。

家の価格予測の例で見てみましょう。

ML は家を直接見るわけではなく、人がまとめた家の特徴量だけを受け取ります。そして過去のデータから学習して、与えられた特徴量がどんな結果につながるかを予測します。

例えば、家が広いほど高くなる傾向や、駅から遠いほど安くなる傾向を学んで、価格を予測するイメージです。

![](/images/ai-ml-dl-llm-basics/ml-features-house-price.png =600x)
*ML による家の価格予測の流れ*

ここで、特徴量から結果を予測する計算を実際に行うのが**モデル**（***model***）です。

モデルとは、入力を受け取って出力を返す計算装置で、**計算式 + 数字**（**パラメータ**）のセットです。家の価格の例だと、こんな感じです。

![](/images/ai-ml-dl-llm-basics/model-house-price-formula.png =649x)
*家の価格を予測するモデルの例（数値はイメージです）*

ここで点線の中の数字をパラメータ（*parameter*）と言い、過去のデータから学習して決まります。例えば `広さ × 30万` は「1㎡ 広いと 30万円高くなる」、`駅徒歩 × −20万` は「駅から 1分遠いと 20万円安くなる」という学習の結果です。

このように、特徴量を人が決める ML（この記事では「従来の ML」と呼びます）は、モデルを使ってそれぞれの特徴量が結果とどう関係しているかは学べます。しかし、その**特徴量を自分で作ることはできない**です。

![](/images/ai-ml-dl-llm-basics/ml-table-vs-photo.png =700x)
*同じ家でも、渡し方によって予測できるかどうかが変わる*

なので従来の ML で役に立つ予測をするためには、特徴量を人がまとめてあげる必要があります。

## 3. ディープラーニング(Deep Learning)

だったら、特徴量も機械に作らせればいいですよね。そうやって**特徴量まで自分で作らせる技術を、表現学習**（***representation learning***）と言います。

家の価格予測の例をもう一度見てみましょう。

同じ家でも、表現はいろいろあります。ピクセル数百万個の写真（表現 A）かもしれないし、人が特徴量をまとめた表（表現 B）かもしれません。同じ家なのに、ML に表現 B を渡せば価格を予測できて、表現 A を渡すと予測できません。このように、**どんな表現で渡すかが性能を左右**します。


![](/images/ai-ml-dl-llm-basics/ml-vs-representation-learning.png =700x)
*従来の ML と表現学習の違い*

表現学習では、**データをどんな表現に変えれば予測が上手くいくかまで機械がデータから学びます**。

ただ、数百万個のピクセル（写真）から家の価格まではあまりにも遠いので、一度に変えるのは難しいです。なので、少しずつ何回かに分けて変えます。この一段階一段階を層（*layer*）と言い、層を深く積み重ねて学習するのでディープラーニング（DL、*Deep Learning*）という名前が付きました。

![](/images/ai-ml-dl-llm-basics/deep-learning-layers.png =496x)
*層を重ねて少しずつ特徴量を作っていくイメージ*

DL は表現学習の一種です。データから一段階ですぐ特徴量を作る浅い表現学習もありますが、何段階も重ねて特徴量を作る方法が DL です。

従来の ML ではモデルが「特徴量 → 結果」の部分だけを担当していましたが、DLでは「データ → 特徴量 → 結果」の全部をモデルが担当することになり、モデルの役割が広がりました。

## 4. LLM (Large Language Model)

それでは、DL の一種であり最近一番話題になっている LLM について見ていきましょう。

### 言語モデル

LLM は *Large Language Model* の略で、大規模言語モデルという意味です。では、そもそも言語モデルとは何でしょうか？

言語モデルは、**前の単語を見て、次の単語を予測するシステム**です。

![](/images/ai-ml-dl-llm-basics/llm-next-word-candidates.png =395x)
*次の単語の候補*

ここでいう予測の結果は、確率分布です。

言語モデルは「次の単語はこれだ！」といきなり一つだけ選ぶわけではありません。自分が知っているすべての単語の候補に確率をつけて出します。この**候補ごとに確率をつけたリストを確率分布**と言います。

![](/images/ai-ml-dl-llm-basics/llm-probability-distribution.png =539x)
*次の単語の確率分布（数値はイメージです）*

この確率分布を使って長い文章を作る方法はシンプルです。**一つ選んで、くっつけて、また予測する、を繰り返します**。

![](/images/ai-ml-dl-llm-basics/llm-autoregressive-generation.png =700x)
*予測して、選んで、くっつけるを繰り返す（数値はイメージです）*

ここでいう「選ぶ」は確率に沿って抽選することで、これをサンプリング（*sampling*）と呼びます。

大事なのは、**一番確率が高い単語が必ず選ばれるわけではない**ということです。たまに 2番目や 3番目の単語が選ばれることもあります。同じ質問でも AI の回答が毎回違うのはこれが理由です。

:::details 🙋‍♀️なんで一番確率が高い単語を確実に選ばずに、ある程度ランダムに選ぶんですか？
一番確率が高い単語だけを選ぶ方法もあります。**グリーディデコーディング**（***greedy decoding***）と呼ばれる方法で、毎回一番確率が高い単語を選ぶ、一番シンプルな生成方法です。

ですが、LLM では広くは使われてないです。理由は 2つあります。

1. 文章がありきたりで、同じ言葉を繰り返してしまう
2. いつも同じ答えが返ってくる

一言で言うと、**1回の答えがつまらないし、何回聞いても多様性がない**ということです。LLM が使われるほとんどの用途で、人はある程度多様性がある方法を好みます。

なので、グリーディデコーディングではなくサンプリングが選ばれたわけです。
:::

このように自分が作った単語をまた入力に使いながら順番に生成するモデルを、自己回帰（*autoregressive*）モデルと呼びます。今一番よく使われているのも、このタイプです。

### 「大規模」言語モデル

LLM も言語モデルですが、「**大規模**」言語モデルですよね。ここでいう大規模には 2つの意味があります。

1. モデルが大きい（層が多く、パラメータが多い）
2. データが大きい（とてつもない量のテキストで学習した）

ここでいう「多い」は本当にとてつもないレベルです。例えば Llama 3.1 405B というモデルは 4,050億個のパラメータを持っていて、15兆個を超えるトークンで学習しています。

言語モデルをこんなに大規模にした主な理由は**性能**です。次の 3つの要素が、モデルの性能を主に決めるからです。

1. モデルの大きさ（パラメータの数）
2. データの量（学習したテキストの量）
3. 計算量（学習に使った計算 = どれだけ長く、たくさん回したか）

3つのどれを増やしても性能が良くなるので、モデルもデータもどんどん大きくなったわけです。

でも、モデルが大きくなるとその代償もあります。大きいモデルは使うたびにコストがたくさんかかります。なので、あえて小さいモデルを作って、もっと多くのデータでもっと長く学習させる、という選択をすることもあります。

ちなみに LLM がディープラーニングの一種なのは、たくさんの層を重ねて、段階的に特徴量を作りながら次の単語を予測しているからです。

![](/images/ai-ml-dl-llm-basics/llm-layers.png =569x)
*LLM の中の層のイメージ（各層の説明はイメージです）*

### ローカル LLM

さて、先ほどモデルは「計算式 + 数字（パラメータ）」のセットという話をしました。この数字（パラメータ）の一覧が公開されているかどうかで、モデルは 2種類に分かれます。

- **open-weight モデル**
  - 作った会社が数字（パラメータ）の一覧を公開している
  - 誰でもダウンロードして、自分のパソコンで動かせる
- **closed-weight モデル**
  - 作った会社が数字（パラメータ）の一覧を公開していない
  - Web、アプリ、API を通してしか使えない

私たちがよく使う Claude は closed-weight の一例です。数字（パラメータ）の一覧は公開されていなくて、私たちはアプリや API で質問を送って答えを受け取っています。

![](/images/ai-ml-dl-llm-basics/closed-vs-open-weight.png =700x)
*closed-weight と open-weight の使われ方の違い*

ということは、open-weight モデルだとダウンロードして自分の PC で動かせますね。このように **open-weight モデルを自分の PC にダウンロードして動かすことをローカル LLM** と言います。ローカル LLM を使う理由は、大きく次の 3つです。

1. プライバシー（データを外部のサーバーに送らなくていい）
2. 遅延（インターネットの往復がない）
3. コスト（クラウドで動かすとお金がかかる）

ただ、ローカル LLM を自分の PC でちゃんと動かすには、（数十億〜数千億個ある）モデルのパラメータを全部メモリに載せないといけません。えげつないですね。パラメータが多いほど（モデルが大きいほど）、必要なメモリも大きくなります。

ローカルで AI を動かすのが流行ったときに Mac Studio と Mac mini が品薄になったのも、大容量メモリの構成に注文が殺到したことが大きな理由です。ブームが始まった頃の Mac Studio は、メモリを最大 512GB まで選べたんですよね。~~（最初はストレージ容量だと思ってた）~~

:::details 🙋‍♀️パラメータを全部メモリに載せるのはやばすぎですが、分けて載せちゃダメなんですか？
分けて載せる方法も実際にあります。分け方は大きく 2つです。

**1. 複数の装置に分けて載せる**
GPU が複数あれば、層（layer）を分けてそれぞれの GPU に載せます。

![](/images/ai-ml-dl-llm-basics/split-layers-gpus.png =600x)
*層を複数の GPU に分けて載せる*

データセンターの大きなモデルは、複数の装置に分けて動かしています。ただ、装置が何台も必要になるので、誰でもできる方法ではないですね。

**2. 一部は別の場所に置いて、必要なときだけ持ってくる（offload）**

![](/images/ai-ml-dl-llm-basics/offload.png =484x)
*offload のイメージ*

こうすれば、GPU や CPU のメモリに入りきらないモデルでも動かすことはできます。でも、デメリットははっきりしています。必要になるたびに持ってくるので、遅くなります（ディスクから持ってくる場合はかなり遅くなることもある）。
:::
